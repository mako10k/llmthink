## 第1条（適用と同意）

1. 本規約は、運営者が試験的に提供するllmthinkのhosted MCPサービスおよびこれに付随する機能
   （以下「本サービス」といいます。）の利用条件を定めます。
2. 利用希望者は、本規約全文および別掲の重要事項要約を確認し、指定された画面で「同意して試験
   利用を開始する」旨の操作をした場合に限り、本サービスを利用できます。
3. WorkOSその他の認証手段によるログイン、規約linkの表示、MCPからの接続要求または本サービスの
   継続利用だけを、本規約への同意とはみなしません。
4. 本規約に同意する者が未成年者その他単独で有効な同意を行えない者である場合、法定代理人等の
   必要な同意を得なければなりません。

2. 本サービスの機能、品質、性能、保存容量、rate limit、対応client、提供時間、提供地域、運用方法

3. 運営者は、本サービスの永続的、継続的または無停止の提供を保証しません。
4. 利用者は、本サービスだけを唯一の保存先とせず、必要なデータを自らarchiveし、復旧可能な状態を
   維持するものとします。

## 第3条（account、認証および利用資格）

1. 利用者は、運営者が指定する外部認証サービスによる本人の認証と、本規約への明示同意を完了する

2. 認証の成功は、それ自体で本サービスの利用資格または個別操作の権限を付与するものではありません。
3. 運営者は、利用者ごとに仮名の内部subject、専用tenantおよび初期workspaceを割り当てます。
4. 利用者は、他の利用者のaccount、tenant、workspaceまたは保存データへアクセスしてはなりません。
5. 利用者は、認証情報、復旧識別子その他のcredentialを適切に管理し、第三者へ開示または共有しては

6. 復旧識別子は、管理者による本人確認・移行判断を補助するものであり、その提示だけで自動的に

1. 利用者は、本サービスへ入力、送信または保存する文章、構造化データその他の情報

3. 利用者が個人情報、秘密情報、第三者の著作物その他取扱いに注意を要する情報を入力する場合、その

4. 前項は、運営者が負うアクセス制御、tenant分離、通信および保存データの秘匿性、安全管理、事故対応

利用者は、次の行為をしてはなりません。

2. 第三者の権利、privacy、秘密または信用を侵害する行為

   範囲と方法を明示的に許可したsecurity testを除きます

   危害を与える行為
6. 運営者が別途明示的に許可していない再販売、第三者向けservice提供またはaccount貸与

## 第6条（利用制限、停止およびaccount終了）

1. 運営者は、規約違反、security incident、abuse、不正アクセスのおそれ、法令上の要請、provider障害、
   容量不足、保守その他合理的な理由がある場合、利用の全部または一部を制限または停止できます。
2. 緊急対応が必要な場合、運営者は事前通知なく停止できます。緊急性がない場合は、可能な範囲で理由、
   影響および見込みを通知します。
3. 利用者は、指定された方法によりaccount終了を申し出ることができます。運営者は、本人確認、archive、
   未解決incidentおよび法定保存のために必要な手続を求めることがあります。
4. account終了後の利用者データは、第10条およびprivacy noticeに従って削除または隔離します。

## 第7条（本サービスの変更）

1. 運営者は、試験結果、security、法令、provider、費用、容量または運用上の必要に応じ、本サービスの
   内容を変更できます。
2. 利用者の権利義務に重大な影響を与える変更については、合理的な方法で事前に通知します。ただし、
   緊急のsecurity対応、法令上の要請その他事前通知が困難な場合を除きます。
3. 機能、保存期間、データ取扱い、責任範囲、料金または終了条件の重大な変更は、新しい規約versionとし、
   対象利用者の再同意を必要とします。
4. 再同意が完了するまで、運営者は通常のread、write、finalizeおよびaudit操作を停止できます。この場合も、
   合理的に可能な範囲で、規約表示、データarchive、account終了の手段を提供します。

3. 運営者は第三者serviceを適切に選定・設定し、必要な監督および安全管理に努めますが、第三者serviceの

## 第10条（archive、終了およびデータ保持）

1. 運営者が本サービスを終了し、または利用者データとの互換性を失う重大変更を行う場合、法令、security
   incident、providerの突然の停止その他不可能な事情がない限り、原則として14日以上前に通知し、
   通知日から30日以上のarchive取得期間を設けます。
2. archiveは、合理的な機械可読形式で提供するよう努めます。ただし、第三者の権利、security情報、内部
   credential、他tenantの情報および法令上提供できない情報は含みません。
3. archive期間終了後、運営者は運用中の利用者データを削除できます。backup、監査記録、同意証跡および
   法定保存対象は、privacy noticeに定める期間、分離・保護して保持する場合があります。
4. 利用者は、終了通知の有無にかかわらず、重要な利用者データを定期的にarchiveするものとします。

2. 運営者は、通信内容および保存データについて、適用される通信の秘密、秘密保持、安全管理および

4. 漏えい、滅失、毀損、不正アクセスその他のincidentが発生した場合、運営者は原因、影響範囲、必要な

2. 本サービスのauditまたはLLM関連出力は、利用者の判断を補助するものであり、法律、医療、金融、security
